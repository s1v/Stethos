# Stethos 仕様書（開発者向け）

> No install needed. Read live vehicle data from BLE OBD2 adapters right in your browser via Web Bluetooth.

利用者向けの説明は [README.md](../README.md)（英語版 [README.en.md](../README.en.md)）を参照。公開 URL：<https://s1v.github.io/Stethos/>
本書は仕様と開発・運用の手順をまとめたもの。

---

## 1. 概要
| 項目 | 内容 |
|---|---|
| アプリ名 | **Stethos**（聴診器 / Stethoscope に由来。「車の聴診器」） |
| 形態 | GitHub Pages で公開する静的 Web アプリ（HTML / CSS / JS、SPA、ビルド不要） |
| バージョン | 0.0.28（`sw.js` の `APP_VERSION`、`js/version.js`、トップ画面・設定画面のフッター表示） |
| 言語 | 日本語 / English（14 章） |
| リポジトリ | https://github.com/s1v/Stethos |
| ライセンス | GPL-3.0（ルートの `LICENSE`。設定画面の一番下に「© 2026 s1v ／ GPL-3.0 License」と表示し、GitHub 上の LICENSE にリンク） |
| PWA | **必須**（ホーム画面への追加、全画面表示、オフラインでの起動） |
| 配信 | ストア配信なし（URL を開くだけで使える） |
| 対象車両 | 車種を限定しない（OBD-II 対応車） |
| 開発に使う車 | ボルボ V90 Cross Country |

## 2. 動作環境
| 環境 | 対応 | 備考 |
|---|---|---|
| Android + Chrome | ◯ | URL を開くだけで使える |
| Android + Edge / Samsung Internet | ◯ | おおむね対応 |
| iPhone + Safari / Chrome | ✕ | WebKit が Web Bluetooth 非対応 |
| iPhone + **Bluefy** | ◯ | 無料の Web Bluetooth 対応ブラウザ |
| PC + Chrome / Edge | ◯ | 開発・デバッグ用 |

- 非対応ブラウザで開いた場合は、対応ブラウザを案内する（お試しモードは非対応ブラウザでも使える）。
- GitHub Pages は HTTPS なので、Web Bluetooth と Service Worker の HTTPS 必須という条件を満たしている。

## 3. 対応アダプター
- **ELM327 互換の BLE 版のみ**
  - Bluetooth Classic（SPP）版：✕（Web Bluetooth は BLE 専用）
  - Wi-Fi 版：✕（ブラウザは生の TCP 通信ができない。HTTPS から暗号化なしのローカル通信もブロックされる）
- 開発用の実機：**JFIND JF327**（BLE、Bluetooth 5.1、PIC18F25K80、V1.5）
  - UUID は実機を nRF Connect で確認予定（確認後 `js/config/known-uuids.js` に記入）

## 4. 画面構成（SPA）
ページを移動すると BLE の接続が切れるため、**1 ページ内で表示を切り替える**。画面切り替え時は全画面を一度非表示にしてから対象を表示する。

### 4.1 画面一覧
| 画面 | 役割 | 表示タイミング |
|---|---|---|
| トップ | 言語の切り替え、接続まわり（確認事項・詳細設定・接続ボタン・UUID 管理への導線）、お試しモードの入口 | 起動時・切断後 |
| UUID 入力 | 未登録アダプター用の UUID 入力 | 既知の UUID が見つからなかったとき |
| UUID 管理 | 保存した UUID の一覧・削除 | トップから移動 |
| ホーム | 車両・対応表示項目数・車の状態・ミニメーター | 接続完了後 |
| ステータス | カテゴリ一覧 → カテゴリ内の項目をリアルタイム表示 | メニュー・ホームから移動 |
| マイページ | 利用者が選んだ項目を並べた画面（プリセット複数） | メニューから移動 |
| 診断情報 | 故障コード（DTC）の一覧・消去 | メニュー・ホームから移動 |
| 設定 | 言語、テーマ、文字サイズ、マルチ PID 通信、マイページのリセット | メニューから移動（接続中のみ） |

### 4.2 画面の遷移
```
[トップ] ──→ [UUID 管理] ──→ [トップ]
   │
   │ 接続
   ├──（未登録）→ [UUID 入力] → 再選択 ─┐
   ▼                                  │
[ホーム] ←────────────────────────────┘
   │  ├ 車の状態の「故障コード」「チェックランプ」行 → [診断情報]
   │  └ 対応表示項目数（ステータス一覧 ›）→ [ステータス]
   │
   │ 右上のメニュー（js/config/menu.js）
   ├ ホーム / ステータス / マイページ / 診断情報 / 設定
   └ 切断 → 確認 → [トップ]
```

**ブラウザの戻る・進む（History API）**
- 画面を切り替えるたびに `history.pushState({screen})` で履歴に積む（URL は変えない）。`popstate` で該当画面を表示する
- 接続中の画面どうしは普通に戻る・進むできる。ステータスのカテゴリの出入りも履歴に積む（画面定義の `historyParams: true`）
- 接続中にトップ側の画面へ戻ろうとした場合は、切断の確認ダイアログを出す（キャンセルなら今の画面に留まる）
- 切断後に、接続中だった画面へ「進む」ことはできない
- ダイアログ・シートが開いているときの「戻る」は、それを閉じる

### 4.3 共通ヘッダー（接続後の画面）
- 左：画面名（マイページはプリセット名、ステータスの 2 段目はカテゴリ名）、接続状態、更新速度（ステータス・マイページ表示中のみ「更新 n 項目/秒」）、お試しモード中は「TEST」バッジ
- 右上：メニューボタン（ハンバーガー）。項目は `js/config/menu.js` のデータから生成する
- メニューボタンの左に、画面ごとのボタンを置く
  - 「?」：画面モジュールに `help: { title, text }` がある画面だけ表示（現在はマイページ）
  - プリセット切り替え（4 マスのアイコン）：マイページのみ
- 予期せず接続が切れた場合は、通知を表示してトップ画面へ戻る

### 4.4 トップ画面（上から順に）
1. 右上：言語トグル（JA / EN）
2. ロゴ・アプリ名（説明文は置かない。アイコンと名前の間は詰める）
3. （非対応ブラウザのみ）対応ブラウザの案内
4. **接続まわりのブロック**（外側の 1 ブロックの中に次を並べる）
   1. 接続の前に確認（情報カード。確認事項のみ）
      - BLE（Bluetooth 5.1）対応アダプターを車の OBD ポートに挿している
      - エンジン（イグニッション）が ON
      - 他の OBD アプリは閉じている
   2. 詳細設定（折りたたみ・任意）：今回の接続で使うサービス UUID。接続に成功した UUID は保存され、次回以降は入力不要である旨を表示
   3. 接続ボタン
   4. 保存した UUID を管理（リンク）
5. お試しモードの入口（状況の選択と「お試しで起動」を横並び。狭い画面では縦並び）
6. 「走行中は画面を操作しないでください。」とバージョン

### 4.5 ホーム画面
上から次の順に並べる。

1. 「車両」（メーカー・年式の推定、VIN、車種を調べる）｜「対応表示項目数」（例：18 / 20 項目。「ステータス一覧 ›」でステータスへ）を横並び
2. 車の状態：故障コード / チェックランプ / バッテリー / 冷却水温を緑・黄・赤で判定し、一番悪い状態をカード全体の色と見出しにする（全部緑なら「異常なし」）。故障コード・チェックランプの行はタップで診断情報へ
   - バッテリー（ATRV）：作動中は 13.2〜15.0 V で充電中、13.2 V 未満は充電不足（黄）、15.0 V 超は過充電の疑い（赤）。停止中は 12.4 V 以上で良好、12.0 V 以上でやや低い（黄）、12.0 V 未満で充電不足（赤）
   - 冷却水温：60°C 未満は「暖機中」（行の印だけ黄。全体の判定は緑のまま）、105°C 以下は正常、115°C 以下は高め（黄）、それ以上は過熱の疑い（赤）
3. ミニメーター：車速・回転数・冷却水温・バッテリー電圧の針式メーター。ホーム表示中だけこの 4 項目を取得する。単位は利用者が選んだ単位
- VIN は接続のたびに車から読み取る（端末には保存しない）
- 車種の照会結果は VIN ごとに保存し、次回からは照会しない（見つからなかった結果も保存）

### 4.6 ステータス画面
- **2 段構成**（多数の PID を取得し続けると ECU の負荷になるため、取得は選んだカテゴリの分だけにする）
  - 1 段目：カテゴリの一覧（アイコン・名前・「対応数 / 項目数」）。この段では車に問い合わせない。対応項目が 0 のカテゴリは薄く表示
  - 2 段目：選んだカテゴリの項目だけを取得・表示。上部に「‹ カテゴリ一覧」。対応していない項目は下に畳んで表示
- カテゴリ（`pids.js` の `PID_GROUPS`、アイコンは `js/screens/parts/icons.js`）は 15 個：走行 / アクセル・スロットル / エンジン / バッテリー・電気 / 温度 / 吸気・過給 / 燃料 / 燃料補正 / 燃料圧力 / エバポ（燃料蒸発ガス） / O2・空燃比センサー / 排気・後処理 / 距離・時間 / 診断・システム / 車両情報
- 表示中は Wake Lock で画面を点けたままにする（画面には表示しない）

#### 4.6.1 表示ブロック（ステータス・マイページ共通、`js/screens/parts/pid-card.js`）
- ブロックは**正方形**（名前は上に 2 行分、数値は中央、インジケーターは下）。「?」アイコンは置かず、ブロック全体をタップすると詳細画面を開く
- 項目名は常に 2 行分の高さを確保（1 行でも 2 行でも数値・インジケーターの位置は同じ）。3 行以上は省略
- 「°」は数値と同じ大きさで直後に付ける（°C の C は単位の大きさ）
- 数値と単位が収まらないときは、単位を次の行に折り返す。時間の項目は「時間・分・秒」に分け、収まらないところで折り返す
- インジケーター（下部のバー）は `pids.js` の `min`〜`max` を両端とした現在値の位置。規格上の範囲ではなく、一般的な車で実際に取りうる範囲を目安に設定している。バーのない項目（文字表示など）も同じ高さを確保する
- ブロックの最小幅は 104px（文字サイズの倍率に合わせて広がる）、間隔は 6px

#### 4.6.2 詳細画面
- ブロックをタップして開く画面。並びは「タイトル・数値・説明・表示単位」
- 数値は開いている間 0.5 秒ごとに更新する（ブロックに収まりきらない値もここで全部読める）
- 表示単位：項目ごとに単位を選べる（localStorage `stethos.units.v1`。ステータス画面・マイページ・ホームのミニメーター共通）
  - 定義は `js/config/units.js`。取得・計算は常に基本単位で行い、表示時だけ変換する（バーの位置は変わらない）
  - 対象：温度（°C / °F）、圧力 kPa（kPa / bar / psi / kgf/cm²）、圧力 Pa（Pa / kPa / inH2O）、速度（km/h / mph）、距離（km / mi）、トルク（Nm / kgf·m / lb·ft）、燃料消費量（L/h / gal/h）、空気量（g/s / kg/h / lb/min）
- ダイアログ・シートは**背景のタップ**や**ブラウザの戻る**でも閉じられる

### 4.7 マイページ（カスタム画面）
- 利用者が任意のステータス項目を選んで、好きな位置に並べられる画面
- 使い方の説明は、ヘッダーの「?」ボタンで開くダイアログに表示する（画面内には書かない）
- 初期状態は空の枠 12 個のグリッド。空の枠をタップ → 項目選択シート（カテゴリごとの折りたたみで初期状態はすべて閉じる。見出しに「対応数 / 項目数」。車が対応していない項目は選べない。配置済みの項目には「配置済み」）→ 表示の種類を選ぶ
- 配置済みの枠をタップ → 「説明を見る・単位変更」（単位を切り替えられない項目は「説明を見る」）／「表示の種類を変更」／「別の項目に変更」／「この枠から外す」
- 「枠を追加」（横幅いっぱいのボタン）で 3 枠ずつ増やせる。リセットは設定画面から行う
- 配置した項目だけを取得する（計算項目は必要な基本項目を自動で取得）。表示中は Wake Lock

#### 4.7.1 表示の種類（`js/screens/parts/widgets.js`）
- 数値（1×1）／大きな数値（2×1）／縦バー（1×2）／グラフ（2×1、直近 60 点と最小・最大）／メーター（2×2、ホームのミニメーターと同じ部品）／大きなグラフ（2×2、直近 120 点）
- 文字の項目（enum・text・hex・時間）は「数値」「大きな数値」のみ
- マスは正方形。列数は画面幅と文字サイズの設定から決め（最低 2 列）、大きな項目は空いたマスに詰めて並べる（CSS grid の dense）。大きな項目も枠は 1 つ

#### 4.7.2 プリセット（複数のマイページ）
- メニューの「マイページ」：プリセット一覧の一番上のプリセットをそのまま開く（毎回選ばない）
- ヘッダーの切り替えボタンでプリセット一覧（下から出るシート）を開く。表示中のプリセットは強調表示。選ぶと切り替える
- 各行の「…」で「名前を変更」「このプリセットを削除」（確認あり。最後の 1 つを消すと空のプリセットを作り直す。表示中のものを消したら一番上に切り替える）。ヘッダーのプリセット名からは変更しない
- 一覧の一番下の「＋ プリセットを追加」で名前を入力して新規作成し、そのまま開く
- 保存先は localStorage `stethos.mypage.v2`（`{ presets: [{ id, name, slots }], last }`。`slots` は枠ごとに `null` / `{ key, style }`）。旧形式（`stethos.mypage.v1`、文字列 key の配列）は「マイページ 1」の「数値」として引き継ぐ

### 4.8 設定画面
- 接続中にメニューの「設定」から開く（トップ画面には導線を置かない）
- 言語：日本語 / English（14 章）
- 表示：**ステータス項目の文字サイズ**（小 / 中 / 大。倍率 1.0 / 1.2 / 1.45）。ステータス画面・マイページのブロックに反映し、プレビューを表示
- 通信：**マルチ PID 通信**のオン / オフと、現在の状態（使用中 / オフ / 使えないため 1 項目ずつ取得中）（9.2 参照）
- アダプターの動作報告（4.12）
- マイページ：**マイページをリセット**（確認あり。すべてのプリセットを削除し、空のマイページ 1 つ・12 枠に戻す）
- 設定は localStorage `stethos.settings.v1` に保存（言語のみ `stethos.lang`）

### 4.9 診断情報画面
- 最上部に**診断サマリー**（状態色の左帯・アイコン・状態文言、故障コード件数と MIL）
  - 異常なし：緑 ✓ ／ 故障コードあり：黄 ! ／ MIL 点灯：赤 !
- DTC の一覧（コード、共通 / メーカー独自の区別、共通コードは説明文）
- 再読み込みボタン
- DTC 消去ボタン（確認ダイアログを必ず挟む）

### 4.10 UUID 入力画面
- 「未登録のアダプター」ラベル付きの**黄色の破線カード**で、通常とは異なる手順であることを示す
- 「選んだ機器：」は太字、機器名は太字＋下線
- 入力欄の下に UUID の説明（ヒント）と、保存され次回以降は入力不要である旨
- nRF Connect での調べ方（折りたたみ）。「キャラクタリスティック」という用語は使わず、「WRITE（送信）」「NOTIFY（受信）」と表示される項目、と説明する

### 4.11 UUID 管理画面
- 最上部に「アダプターの動作報告」（4.12）
- 保存した UUID の一覧（UUID、接続した機器名、保存日時）と個別削除（確認ダイアログあり）
- 既知の UUID リストは**折りたたみ（初期状態は閉じる）**で参考表示のみ。確認状況は表示しない
### 4.12 アダプターの動作報告（`js/report.js`）
- 接続に成功するたびに、報告用の情報を localStorage `stethos.lastConn.v1` に保存する（機器名、サービス UUID、マルチ PID の状態）。Issue には車・端末の情報（VIN、車種、ブラウザなど）を入れない
- UUID 管理画面と設定画面に「最後に接続したアダプター」として表示し、「このアダプターの動作を報告 ›」で GitHub の Issue フォーム（`adapter-report.yml`）を新しいタブで開く。フォームの `uuid` と `notes`（アプリのバージョンとマルチ PID の状態）は URL のパラメーターで入力済みにする。タイトルは「[アダプター] UUID」
- 利用者は GitHub 上で「動作結果」を選び（製品名は任意）、内容を確認してから送信する（送信には GitHub アカウントが必要）
- 開く前に確認ダイアログを出す（アカウントが必要なこと、車や端末の情報を送らないこと、接続中に離れると切断されることがあること）
- お試しモードの接続は報告できない
- 報告後の流れ（`accepted` ラベル → PR 自動作成）は開発・運用ガイド G

## 5. 接続の流れ
### 5.1 一覧の表示と UUID の宣言
| 設定 | 役割 | 本アプリの仕様 |
|---|---|---|
| 一覧に何を表示するか | どの機器を一覧に並べるか | **全ての BLE 機器を表示**（`acceptAllDevices: true`） |
| どのサービスを使うか（宣言） | 接続後にアクセスできるサービス | 下記 3 種類の UUID を `optionalServices` にまとめて宣言 |

- 宣言は一覧の表示には影響しない。宣言にない機器も一覧に出て、接続もできる。
- ただし、接続後に使えるサービスは宣言した UUID だけ（宣言していないと SecurityError）。

宣言する UUID：① 既知の UUID リスト ／ ② 保存済みの UUID ／ ③ 詳細設定で入力した UUID

### 5.2 手順
1. 接続ボタンを押す
2. Web Bluetooth の一覧を開く（全機器を表示、①〜③を宣言）
3. 利用者がアダプターを選ぶ
4. 宣言したサービスがあるか確認する

**A. 既知の UUID が見つかった場合**
5. 送信用（write / writeWithoutResponse）と受信用（notify / indicate）のキャラクタリスティックを性質から自動で判別する
6. `ATZ` などで ELM327 の応答を確認し、初期化する（`ATE0` `ATL0` `ATS0` `ATH0` `ATAT1` `ATSP0` → `0100`）
7. 対応 PID・VIN を取得し、マルチ PID 通信が使えるか試してからホーム画面へ（③で接続できた場合はその UUID を保存）

**B. 既知の UUID が見つからなかった場合**
5. UUID 入力画面を表示する
6. UUID を入力して「接続」を押す
7. **一覧がもう一度開く**（入力した UUID を宣言に加えるため）
8. 同じアダプターを選び直す
9. 入力した UUID で確認し、OK なら localStorage に保存する
10. ホーム画面へ

### 5.3 選ぶ回数
| 利用者 | 流れ | 選ぶ回数 |
|---|---|---|
| 既知のアダプター（大多数） | 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知っている | 詳細設定で入力 → 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知らない | 接続 → 選ぶ → 入力 → もう一度選ぶ | 2 回（初回のみ） |

`js/config/known-uuids.js` で管理する（サービス UUID のみ）。

- 動作報告は GitHub の Issue（テンプレート「アダプターの動作報告」）で受け付ける。`status` は管理用で画面には出さない。

## 7. UUID 入力・管理の仕様
- 入力するのは**サービスの UUID のみ**
- 4 桁 / 8 桁 / 32 桁（ハイフンなし）/ 36 文字の形式を受け付け、128bit の小文字に正規化する

## 9. 表示するデータ
### 9.1 ステータス項目（Mode 01 ＋ アダプター測定値）
- 対象範囲：Mode 01 の PID 01〜A9（範囲指示用の 20/40/60/80/A0 を除く）のうち、参考記事（みんカラ「OBD2 PID 一覧」 https://minkara.carview.co.jp/smart/userid/3405966/blog/46655889/ ）に載っている全 PID に対応。項目数は計 184（計算項目・アダプター測定値を含む）
- 表示形式（`format`）：数値（既定）／`enum`（対応表）／`text`（ビットや複数値を文章で表示）／`duration`（時間・分・秒）／`hex`（受け取ったデータを 16 進数のまま表示）
- 計算式は公開情報（DashLogic「OBD-II J1979 PID Listing」 https://www.dashlogic.com/docs/technical/obdii_pids 、Wikipedia「OBD-II PIDs」、CSS Electronics）から取り込んだ。複数の値をまとめて返す PID は、`pids.js` の `F()` で 1 フィールドずつ項目にする（`at`：値の位置、`n`：バイト数、`bit`：先頭バイトのどのビットで有無を示すか）。車が返していないフィールドは「--」
- `hex` のまま残している PID（公開情報で中身を確認できないもの）：7B, 7D, 7E, 9A, A1, A3, A7, A8
- 有償の規格書（SAE J1979 / ISO 15031-5）の無断転載と思われるものは参照しない
- 同じ PID から複数の項目を取るときは、同じ周の応答を使い回して問い合わせを 1 回にする（`obd.js`）。取得順も PID 順に並べる（`poller.js`）
- 項目とカテゴリの対応は `pids.js` の各定義の `group` を正とする（カテゴリ一覧は 4.6）
- VIN は Mode 09 PID 02 で取得（ホーム画面）
- 車ごとの対応項目は `0100` / `0120` / … / `01C0` で確認する

**バッテリー項目の考え方**
- `ATRV`（アダプターが OBD ポートで測る電圧）は PID 非対応の車でも取れるため、常に表示する
- 12V 充電量（推定）：エンジン停止中（回転数 0 または取得不可）の電圧から 11.8 V＝0%〜12.7 V＝100% で線形推定。作動中は「--」
- 充電状態：作動中の電圧で判定（13.2〜15.0 V 充電中 ／ 13.2 V 未満 充電不足 ／ 15.0 V 超 過充電の疑い）。停止中は「停止中」
- 劣化具合（SOH）・始動能力（CCA）は負荷試験が必要なため OBD では測れない
- PHEV の駆動用バッテリー（例：ボルボ T8）の詳細はメーカー独自の Mode 22 が必要（9.5 参照）

### 9.2 マルチ PID 通信
- Mode 01 の 1 回の問い合わせに最大 6 個の PID を入れて取得する（例：`010C0D05`）。BLE とアダプターの往復が減り、更新が速くなる。ECU への問い合わせ回数も減る
- 使う条件：設定「マルチ PID 通信」がオン（既定）、かつ通信方式が CAN（`ATDPN` が 6〜9 / A〜C）、かつ接続時のテスト（2〜3 個の PID をまとめて送り、全部正しく返る）に合格
- まとめるのは、データ長が確実な PID だけ（`obd.js` の `PID_LEN`）。それ以外・複数の値を返す PID・16 進表示の PID は 1 個ずつ問い合わせる
- 応答は「41 PID データ PID データ…」を `PID_LEN` で区切る。CAN の複数フレーム（`0:` `1:` …）にも対応。末尾の詰め物（00 / 55 / AA）は無視。複数の ECU が答えたときは最初の応答を使う
- 3 回続けて読み取れなかったら、その接続中は自動で 1 個ずつの方式に戻す
- 取得の流れ（`poller.js`）：1 周ごとに応答キャッシュを捨て、まとめて送れる PID を先に 6 個ずつ取得し、残りを 1 個ずつ取得する。1 周が 50 ms 未満で終わったときは待って空回りを防ぐ
- 接続中に設定を切り替えると、その場で使えるか試す

### 9.3 故障コード（DTC）※診断情報画面
- 読み取り：Mode 03 ／ 消去：Mode 04 ／ MIL と件数：Mode 01 PID `01`
- 形式は共通（P / C / B / U ＋ 4 桁）
- 共通コード（P0xxx、P2xxx、P34xx〜、C0/B0/U0 など）：説明文つき（`js/config/dtc-codes.js`）
- メーカー独自コード（P1xxx、P30xx〜P33xx など）：コードのみ表示
- 汎用 OBD で読めるのは主にエンジン系（排ガス関連）

### 9.4 車両情報
- VIN の先頭 3 文字（WMI）からメーカーを推定（`js/config/wmi.js`）、10 文字目から年式を推定（30 年周期のため現在年 +1 以下の最新年を採用）
- 車種名は VIN だけではオフラインで判定できないため、利用者の操作で NHTSA vPIC API に問い合わせる。北米向け以外の車は返らないことがある
- 国内専用車など、OBD で 17 桁の VIN を返さない車では「取得できませんでした」と表示

### 9.5 メーカー独自データ
- ボルボ独自の値（T8 のバッテリー残量、タイヤ空気圧など）は Mode 22 が必要で、公開情報が少ない → 「取れたらおまけ」扱い

### 9.6 PID の定義はデータとして持つ
- 各項目（PID、名前、単位、計算式、表示範囲、説明文）は `js/config/pids.js` にまとめる。ステータス画面・マイページ・ホームで同じ定義を使う

- 制限：入力欄の初期値（新しいプリセット名など）は日本語のまま。保存済みのプリセット名「マイページ n」は表示時に「My page n」になる

## C. 更新時の注意
- `sw.js` の `APP_VERSION`、`js/version.js`、`index.html` のバージョン表記（トップ・設定の 2 か所）を更新してから push する（キャッシュ名が変わり、利用者の画面に「更新があります」が表示される）

## D. 既知の UUID を追加する

## E. 表示項目を追加する
`js/config/pids.js` の `PIDS` に定義（pid / key / name / unit / calc / min / max / decimals / group / desc）を追加する。ステータス画面・マイページ・ホームの「対応表示項目数」と、お試しモードの疑似値に自動で反映される。名前・説明文の英訳を `js/i18n/en.js` に追加する。PID 以外の値（`ATRV` など）は `pid` の代わりに `cmd` を指定し、`obd.js` の `readPid` に取得処理を追加する。

## F. お試しモード（コード上の名前は debug。後に削除）
- 画面上の名前は「お試しモード」（英語：Trial mode）。ヘッダーのバッジは「TEST」
- 起動：トップ画面の「お試しで起動」、または URL に `?debug=1`（`&scenario=…` で状況指定）
- 状況：`normal`（DTC あり）/ `nodtc` / `unknown`（UUID 入力画面。疑似 UUID は `ABCD`）/ `connect-error` / `no-elm` / `disconnect`（20 秒後に切断）/ `no-multi`（マルチ PID 非対応アダプター）
- 疑似アダプターは ELM327 のように応答する（初期化、変化する車両データ、VIN、DTC 4 件（共通・メーカー独自）、DTC 消去、マルチ PID の複数フレーム応答）
- **`pids.js` の全項目に対応している車として振る舞う**（項目を追加すると自動で疑似値も返す。値は計算式から逆算して表示範囲内で変化させる）
- 60 秒周期で「エンジン停止 15 秒 → 作動 45 秒」を繰り返し、バッテリー項目の表示も確認できる
- Web Bluetooth 非対応ブラウザでも使える

**削除手順**
1. `js/debug/` フォルダを削除
2. `index.html` の `<!-- DEBUG-START -->` 〜 `<!-- DEBUG-END -->` を削除
3. `js/app.js` 末尾の `// DEBUG-START` 〜 `// DEBUG-END` を削除
4. `sw.js` の `ASSETS` から `./js/debug/mock-adapter.js` を削除し、`VERSION` を更新

## G. Issue テンプレートと既知 UUID の自動登録
**テンプレート**（`.github/ISSUE_TEMPLATE/`）
- `adapter-report.yml`：アダプターの動作報告（製品名〈任意〉・サービス UUID・動作結果〈使えた / 接続はできたがデータが取れない〉・その他）。「この製品なら使える」といった案内はしない（車種によって使えないこともあり、確実な情報を提供できないため）。製品名が空のときは `known-uuids.js` に「利用者の報告」として登録する。ラベル `adapter-report` が付く
- `bug-report.yml`：不具合の報告（ラベル `bug`）
- `feature-request.yml`：要望（ラベル `enhancement`）
- `config.yml`：空の Issue を無効化

**自動登録の流れ**
1. 利用者が「アダプターの動作報告」で Issue を作成（アプリの「このアダプターの動作を報告」から開くと、UUID などが入力済みになる）
2. 管理者が内容を確認し、Issue に **`accepted` ラベル**を付ける
3. ワークフロー `adapter-report.yml` が動き、`add-known-uuid.mjs` が本文から UUID・製品名を取り出して
   - 形式チェック（不正・重複なら Issue にその旨をコメントして終了）
   - `known-uuids.js` の `// @auto-insert` の上に 1 行追加
   - `sw.js` の `BUILD` を +1（利用者のキャッシュを更新するため）
4. ブランチ `adapter/issue-番号` にコミットし、プルリクエストを作成。Issue に PR の URL をコメント
5. 管理者が PR をマージ → `main` への push でデプロイされ、Issue は自動でクローズ

- ラベルを付けられるのは書き込み権限のある人だけなので、第三者が勝手に登録することはできない。最終的にマージするかどうかも管理者が判断する
- 製品名はコードに埋め込むため、記号（`' " \` $ < > { } \`）を除去して 60 文字までに制限する

**初回だけ必要な設定**
1. **Settings → Actions → General → Workflow permissions** で「Read and write permissions」を選び、「Allow GitHub Actions to create and approve pull requests」にチェックを入れる
2. **Issues → Labels** でラベル `adapter-report` と `accepted` を作成する（`bug` `enhancement` は標準で存在する）


## テーマ（スキン）
- 設定画面の「表示 → テーマ」で切り替える。配色・角の形・数字の書体・バー／メーターの描き方を丸ごと変える。**レイアウト（配置・ブロックの大きさ）は変えない**（マイページの配置が崩れないように）。
- 一覧は `js/config/themes.js`、見た目は `css/themes/<id>.css`。各ファイルは `html[data-theme="<id>"]` の下だけに効く CSS 変数と上書きで作る。
- 収録テーマ：スタンダード（`css/style.css` そのもの）／レトロデジタル（黒地に緑の 7 セグ風の発光数字、LED ブロックのバー、破線のメーター）／ターミナル（黒地に緑の等幅、角なし、破線枠、`$` `>` などのコンソール風装飾）
- 外部フォントは使わない（オフライン起動のため）。7 セグ風は等幅＋斜体＋発光で表現する。
- 選んだテーマは設定（`stethos.settings.v1` の `theme`）に保存。起動時のちらつきを防ぐため、`index.html` の `<head>` で読み込み前に `data-theme` を付ける。`<meta name="theme-color">` もテーマに合わせて変える。
- テーマを追加するとき：`themes.js` に 1 行、`css/themes/` にファイル、`index.html` の `<link>`、`sw.js` のキャッシュ対象、設定画面のサンプル用 CSS（`.theme-sw.t-<id>`）を足す。
