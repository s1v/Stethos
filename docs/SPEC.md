# Stethos 仕様書（開発者向け）

> No install needed. Read live vehicle data from BLE OBD2 adapters right in your browser via Web Bluetooth.

利用者向けの説明は [README.md](../README.md) を参照。公開 URL：<https://s1v.github.io/Stethos/>本書は仕様と開発・運用の手順をまとめたもの。

---

## 1. 概要
| 項目 | 内容 |
|---|---|
| アプリ名 | **Stethos**（聴診器 / Stethoscope に由来。「車の聴診器」） |
| 形態 | GitHub Pages で公開する静的 Web アプリ（HTML / CSS / JS、SPA、ビルド不要） |
| バージョン | 0.0.8（`sw.js` の `APP_VERSION` とトップ画面のフッター表示） |
| リポジトリ | https://github.com/s1v/Stethos |
| PWA | **必須**（ホーム画面への追加、全画面表示、オフラインでの起動） |
| 配信 | ストア配信なし（URL を開くだけで使える） |
| 対象車両 | 車種を限定しない（OBD-II 対応車） |
| 開発に使う車 | ボルボ V90 Cross Country |
| GitHub Topics 案 | `obd2` `elm327` `web-bluetooth` `ble` `car` `vehicle-diagnostics` `pwa` `github-pages` |

## 2. 動作環境
| 環境 | 対応 | 備考 |
|---|---|---|
| Android + Chrome | ◯ | URL を開くだけで使える |
| Android + Edge / Samsung Internet | ◯ | おおむね対応 |
| iPhone + Safari / Chrome | ✕ | WebKit が Web Bluetooth 非対応 |
| iPhone + **Bluefy** | ◯ | 無料の Web Bluetooth 対応ブラウザ |
| PC + Chrome / Edge | ◯ | 開発・デバッグ用 |

- 非対応ブラウザで開いた場合は、対応ブラウザを案内する（デバッグモードは非対応ブラウザでも使える）。
- GitHub Pages は HTTPS なので、Web Bluetooth と Service Worker の HTTPS 必須という条件を満たしている。

## 3. 対応アダプター
- **ELM327 互換の BLE 版のみ**
  - Bluetooth Classic（SPP）版：✕（Web Bluetooth は BLE 専用）
  - Wi-Fi 版：✕（ブラウザは生の TCP 通信ができない。HTTPS から暗号化なしのローカル通信もブロックされる）
- 開発用の実機：**JFIND JF327**（BLE、Bluetooth 5.1、PIC18F25K80、V1.5）
  - UUID は実機を nRF Connect で確認予定（確認後 `js/config/known-uuids.js` に記入）

## 4. 画面構成（SPA）
ページを移動すると BLE の接続が切れるため、**1 ページ内で表示を切り替える**。画面切り替え時は全画面を一度非表示にしてから対象を表示する。

**ブラウザの戻る・進む（History API）**
- 画面を切り替えるたびに `history.pushState({screen})` で履歴に積む（URL は変えない）。`popstate` で該当画面を表示する
- 接続中の画面（ホーム / ステータス / 診断情報）どうしは普通に戻る・進むできる
- 接続中にトップ側の画面へ戻ろうとした場合は、切断の確認ダイアログを出す（キャンセルなら今の画面に留まる）
- 切断後に、接続中だった画面へ「進む」ことはできない（トップに留まる）
- ダイアログや処理中表示が出ている間は移動しない

### 4.1 画面一覧
| 画面 | 役割 | 表示タイミング |
|---|---|---|
| トップ | 接続前の確認事項、詳細設定（UUID 指定・任意）、接続ボタン、UUID 管理画面への導線、デバッグモードの入口 | 起動時・切断後 |
| UUID 入力 | 未登録アダプター用の UUID 入力 | 既知の UUID が見つからなかったとき |
| UUID 管理 | 保存した UUID の一覧・削除 | トップから移動 |
| ホーム | **サマリー情報のみ**を表示 | 接続完了後 |
| ステータス | リアルタイムの車両データ | メニュー・ホームから移動 |
| 診断情報 | 故障コード（DTC）の一覧・消去 | メニュー・ホームから移動 |

### 4.2 画面の遷移
```
[トップ] ──→ [UUID 管理] ──→ [トップ]
   │
   │ 接続
   ├──（未登録）→ [UUID 入力] → 再選択 ─┐
   ▼                                  │
[ホーム] ←────────────────────────────┘
   │  ├ DTC タイル → [診断情報]
   │  └ 対応表示項目数タイル → [ステータス]
   │
   │ 右上のメニュー
   ├ ホーム / ステータス / マイページ / 診断情報 / 設定
   └ 切断 → 確認 → [トップ]
```

### 4.3 共通ヘッダー（接続後の画面）
- 対象：ホーム / ステータス / 診断情報
- 左：画面名、接続状態、更新速度（ステータス・マイページ表示中のみ「更新 n 項目/秒」）、デバッグモード中は「DEBUG」バッジ
- **右上：メニューボタン**（ハンバーガーアイコン）。項目は `js/config/menu.js` のデータから生成する
- 予期せず接続が切れた場合も、通知を表示してトップ画面へ戻る

#### 表示の種類（v0.0.13、`js/screens/parts/widgets.js`）
- 枠に項目を置くとき、項目を選んだ後に表示の種類を選ぶ。配置後も「表示の種類を変更」で変えられる
- 種類：数値（1×1）／大きな数値（2×1）／縦バー（1×2）／グラフ（2×1、直近 60 点と最小・最大）／メーター（2×2、ホームのミニメーターと同じ部品）／大きなグラフ（2×2、直近 120 点）
- 文字の項目（enum・text・hex・時間）は「数値」「大きな数値」のみ
- マスは正方形。列数は画面幅と文字サイズの設定から決め（最低 2 列）、大きな項目は空いたマスに詰めて並べる（CSS grid の dense）
- 保存形式：枠ごとに `null` / `{ key, style }`（旧形式の文字列 key は「数値」として読む）

### 4.4 トップ画面（上から順に）
1. ロゴ・アプリ名（説明文は置かない）
2. （非対応ブラウザのみ）対応ブラウザの案内
3. **接続の前に確認**（情報カード。確認事項のみ）
   - BLE（Bluetooth 5.1）対応アダプターを車の OBD ポートに挿している
   - エンジン（イグニッション）が ON
   - 他の OBD アプリは閉じている
4. **詳細設定**（折りたたみ・任意）：今回の接続で使うサービス UUID を入力。接続に成功した UUID は保存され、次回以降は入力不要である旨を表示
5. **接続ボタン**
6. **保存した UUID を管理**（リンク）
7. デバッグモードの入口（削除予定）
8. 「走行中は画面を操作しないでください。」

### 4.5 ホーム画面（サマリー）
上から次の順に並べる。

1. 車の状態（健康診断カード）：故障コード / チェックランプ / バッテリー / 冷却水温を緑・黄・赤で判定し、一番悪い状態をカード全体の色と見出しにする（全部緑なら「異常なし」）。故障コード・チェックランプの行はタップで診断情報へ
   - バッテリー（ATRV）：作動中は 13.2 から 15.0 V で充電中、13.2 V 未満は充電不足（黄）、15.0 V 超は過充電の疑い（赤）。停止中は 12.4 V 以上で良好、12.0 V 以上でやや低い（黄）、12.0 V 未満で充電不足（赤）
   - 冷却水温：60 度未満は暖機中（黄）、105 度以下は正常、115 度以下は高め（黄）、それ以上は過熱の疑い（赤）
2. ミニメーター：車速・回転数・冷却水温・バッテリー電圧の針式メーター（範囲は pids.js の min / max、単位はヒントで選んだ単位）。ホーム表示中だけこの 4 項目を取得する
3. 「接続中のアダプター」と「対応表示項目数（タップでステータスへ）」を横並び
4. 「車両」（メーカー・年式の推定、VIN、車種を調べる）

### 4.6 ステータス画面
- **2 段構成**（多数の PID を取得し続けると ECU の負荷になるため、取得は選んだカテゴリの分だけにする）
  - 1 段目：カテゴリの一覧（アイコン・名前・「対応数 / 項目数」）。この段では車に問い合わせない。対応項目が 0 のカテゴリは薄く表示
  - 2 段目：選んだカテゴリの項目だけを取得・表示。ヘッダーにはカテゴリ名、上部に「‹ カテゴリ一覧」。対応していない項目は下に畳んで表示
- カテゴリ（`pids.js` の `PID_GROUPS`、アイコンは `js/screens/parts/icons.js`）：走行 / アクセル・スロットル / エンジン / バッテリー・電気 / 温度 / 吸気・過給 / 燃料 / 燃料補正 / 燃料圧力 / エバポ / O2・空燃比センサー / 排気・後処理 / 距離・時間 / 車両情報
- カテゴリの出入りはブラウザの戻る・進むでも移動できる（画面定義の `historyParams: true` でパラメーターを履歴に保存）
- 表示中は Wake Lock で画面を点けたままにする

#### 単位の切り替え
- ブロックをタップして開くヒントに「表示単位」を出し、項目ごとに単位を選べる（localStorage `stethos.units.v1` に保存。ステータス画面・マイページ共通）
- 定義は `js/config/units.js`。取得・計算は常に基本単位で行い、表示時だけ変換する（バーの位置は変わらない）
- 対象：温度（°C / °F）、圧力 kPa（kPa / bar / psi / kgf/cm²）、圧力 Pa（Pa / kPa / inH2O）、速度（km/h / mph）、距離（km / mi）、トルク（Nm / kgf·m / lb·ft）、燃料消費量（L/h / gal/h）、空気量（g/s / kg/h / lb/min）

### 4.6.1 表示ブロック（ステータス・マイページ共通、`js/screens/parts/pid-card.js`）
- ブロックは**正方形**（名前は上に 2 行分、数値は中央、インジケーターは下）。右上の「?」アイコンは置かず、ブロック全体をタップすると説明を表示する
- 項目名は常に 2 行分の高さを確保（1 行でも 2 行でも数値・インジケーターの位置は同じ）。3 行以上は省略
- 「°」は数値と同じ大きさで直後に付ける（°C の C は単位の大きさ）
- インジケーター（下部のバー）は `pids.js` の `min`〜`max` を両端とした現在値の位置。規格上の範囲ではなく、一般的な車で実際に取りうる範囲を目安に設定している。バーのない項目（文字表示など）も同じ高さを確保する
- ブロックの最小幅は 104px、間隔は 6px（情報密度を優先）
- タップで説明ダイアログ（単位は表示しない）。ダイアログ・シートは**背景のタップ**や**ブラウザの戻る**でも閉じられる

### 4.6.2 マイページ（カスタム画面）
- 利用者が任意の表示項目を選んで、好きな位置に並べられる画面。メニューの「マイページ」から開く
- 使い方の説明は、ヘッダー右上の「?」ボタンで開くダイアログに表示する（画面内には書かない）
- 初期状態は空の枠 12 個のグリッド。空の枠をタップ → 項目選択シート（カテゴリごとの折りたたみで初期状態はすべて閉じる。見出しに「対応数 / 項目数」を表示。車が対応していない項目は選べない、配置済みの項目には「配置済み」と表示）
- 配置済みの枠をタップ → 「説明を見る」「別の項目に変更」「この枠から外す」
- 「枠を追加」で 3 枠ずつ増やせる。リセットは設定画面から行う
- 配置は localStorage（`stethos.mypage.v1`、枠ごとの項目 key の配列）に保存
- 配置した項目だけを取得する（計算項目は必要な基本項目を自動で取得）。表示中は Wake Lock

### 4.6.2.1 プリセット（複数のマイページ）
- メニューの「マイページ」を押すと**プリセット一覧**（下から出るシート）を表示し、選んだプリセットでマイページを開く。現在のプリセットは強調表示
- 一覧の各行の「…」で「名前を変更」「このプリセットを削除」（確認あり。最後の 1 つを消すと空のプリセットを作り直す）
- 一覧の一番下の「＋ プリセットを追加」で名前を入力して新規作成し、そのまま開く
- マイページのヘッダーには画面名の代わりにプリセット名を表示
- 保存先は localStorage（`stethos.mypage.v2`：`{ presets: [{ id, name, slots }], last }`）。旧形式（`stethos.mypage.v1`）の配置は「マイページ 1」として引き継ぐ

### 4.6.3 設定画面
- 接続中にメニューの「設定」から開く（トップ画面には置かない）
- 表示：**ステータス項目の文字サイズ**（小 / 中 / 大。小が従来の大きさ。倍率 1.0 / 1.2 / 1.45）。ステータス画面・マイページのブロックに反映し、プレビューを表示。ブロックの最小幅も倍率に合わせて広がる
- マイページ：**マイページをリセット**（確認あり。すべてのプリセットを削除し、空のマイページ 1 つ・12 枠に戻す）
- 設定は localStorage（`stethos.settings.v1`）に保存

### 4.3.1 ヘッダーの「?」ボタン
- 画面モジュールに `help: { title, text }` がある画面だけ、ヘッダーのメニューボタンの左に「?」を表示し、タップで説明ダイアログを開く（現在はマイページ）

### 4.7 診断情報画面
- 最上部に**診断サマリー**（状態色の左帯・アイコン・状態文言、故障コード件数と MIL）
  - 異常なし：緑 ✓ ／ 故障コードあり：黄 ! ／ MIL 点灯：赤 !
- DTC の一覧（コード、共通 / メーカー独自の区別、共通コードは説明文）
- 再読み込みボタン
- DTC 消去ボタン（確認ダイアログを必ず挟む）

### 4.8 UUID 入力画面
- 「未登録のアダプター」ラベル付きの**黄色の破線カード**で、通常とは異なる手順であることを示す
- 「選んだ機器：」は太字、機器名は太字＋下線
- 入力欄の下に UUID の説明（ヒント）と、保存され次回以降は入力不要である旨
- nRF Connect での調べ方（折りたたみ）。「キャラクタリスティック」という用語は使わず、「WRITE（送信）」「NOTIFY（受信）」と表示される項目、と説明する

### 4.9 UUID 管理画面
- 保存した UUID の一覧（UUID、接続した機器名、保存日時）と個別削除（確認ダイアログあり）
- 既知の UUID リストは**折りたたみ（初期状態は閉じる）**で参考表示のみ。確認状況は表示しない

## 5. 接続の流れ
### 5.1 一覧の表示と UUID の宣言
| 設定 | 役割 | 本アプリの仕様 |
|---|---|---|
| 一覧に何を表示するか | どの機器を一覧に並べるか | **全ての BLE 機器を表示**（`acceptAllDevices: true`） |
| どのサービスを使うか（宣言） | 接続後にアクセスできるサービス | 下記 3 種類の UUID を `optionalServices` にまとめて宣言 |

- 宣言は一覧の表示には影響しない。宣言にない機器も一覧に出て、接続もできる。
- ただし、接続後に使えるサービスは宣言した UUID だけ（宣言していないと SecurityError）。

宣言する UUID：① 既知の UUID リスト ／ ② 保存済みの UUID ／ ③ 詳細設定で入力した UUID

### 5.2 手順
1. 接続ボタンを押す
2. Web Bluetooth の一覧を開く（全機器を表示、①〜③を宣言）
3. 利用者がアダプターを選ぶ
4. 宣言したサービスがあるか確認する

**A. 既知の UUID が見つかった場合**
5. 送信用（write / writeWithoutResponse）と受信用（notify / indicate）のキャラクタリスティックを性質から自動で判別する
6. `ATZ` などで ELM327 の応答を確認し、初期化する（`ATE0` `ATL0` `ATS0` `ATH0` `ATAT1` `ATSP0` → `0100`）
7. 対応 PID・VIN を取得してホーム画面へ（③で接続できた場合はその UUID を保存）

**B. 既知の UUID が見つからなかった場合**
5. UUID 入力画面を表示する
6. UUID を入力して「接続」を押す
7. **一覧がもう一度開く**（入力した UUID を宣言に加えるため）
8. 同じアダプターを選び直す
9. 入力した UUID で確認し、OK なら localStorage に保存する
10. ホーム画面へ

### 5.3 選ぶ回数
| 利用者 | 流れ | 選ぶ回数 |
|---|---|---|
| 既知のアダプター（大多数） | 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知っている | 詳細設定で入力 → 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知らない | 接続 → 選ぶ → 入力 → もう一度選ぶ | 2 回（初回のみ） |

## 6. 既知の UUID
`js/config/known-uuids.js` で管理する（サービス UUID のみ）。

| サービス UUID | 主な製品 | 確認状況 |
|---|---|---|
| `FFF0` | ELM327 互換 BLE アダプターの多く | 公開情報ベース |
| `FFE0` | HM-10 系モジュール | 公開情報ベース |
| `e7810a71-73ae-499d-8c15-faa9aef0c3f2` | Vgate iCar Pro BLE、OBDLink CX など | 公開情報ベース |
| `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | Nordic UART Service | 公開情報ベース |
| `18F0` / `FFB0` / `FFE5` / `49535343-fe7d-4ae5-8fa9-9fafd205e455` | 一部のクローン・BLE シリアルモジュール | 公開情報ベース |
| （JF327 の UUID） | JFIND JF327 | 実機確認後に記入 |

- 未確認の UUID を宣言しても害はないため、候補は多めに入れておく。
- 動作報告は GitHub の Issue（テンプレート「アダプターの動作報告」）で受け付ける。`status` は管理用で画面には出さない。
- Issue からの自動登録の仕組みは「開発・運用ガイド G」を参照。

## 7. UUID 入力・管理の仕様
- 入力するのは**サービスの UUID のみ**
- 4 桁 / 8 桁 / 32 桁（ハイフンなし）/ 36 文字の形式を受け付け、128bit の小文字に正規化する
- 大文字・小文字や `0x` の有無は自動で整える
- 形式が正しくなければボタンを無効にする
- 接続に成功した UUID だけを localStorage（キー `stethos.savedUuids.v1`）に保存する

## 8. エラーの出し分け
| 原因 | 表示・動作 |
|---|---|
| Web Bluetooth 非対応 | 対応ブラウザ（Android：Chrome、iPhone：Bluefy）を案内 |
| Bluetooth がオフ | オンにするよう案内 |
| 一覧でキャンセル | 元の画面（トップまたは入力画面）に留まる |
| 機器が見つからない・つながらない | イグニッション ON、他の OBD アプリを閉じたかを確認するよう案内 |
| 既知の UUID がない | UUID 入力画面へ |
| 入力した UUID のサービスがない | 入力内容を残して入力画面にエラー表示 |
| 送信・受信の項目がない | 別の UUID を試すよう案内 |
| ELM327 の応答がない | ELM327 互換ではない可能性を案内 |
| 車両の応答がない（`0100` 失敗） | 接続はしたうえで、イグニッション ON を確認するよう通知 |
| 接続中に切断された | 通知を表示してトップ画面へ |

## 9. 表示するデータ
### 9.1 ステータス項目（Mode 01 ＋ アダプター測定値）※ステータス画面

- 対象範囲：Mode 01 の PID 01〜A9（範囲指示用の 20/40/60/80/A0 を除く）のうち、参考記事（みんカラ「OBD2 PID 一覧」 https://minkara.carview.co.jp/smart/userid/3405966/blog/46655889/ ）に載っている全 PID に対応。項目数は計 169（計算項目を含む）
- 表示形式（`format`）：数値（既定）／`enum`（対応表）／`text`（ビットや複数値を文章で表示）／`duration`（時:分:秒）／`hex`（計算式が非公開、または車ごとに中身が違う PID。受け取ったデータを 16 進数のまま表示）
- `hex` の PID：65, 69, 6A, 6B, 6D, 6E, 70, 71, 72, 7B, 7D, 7E, 81, 82, 83, 85, 86, 88, 89, 8A, 8B, 8C, 8F, 90, 91, 92, 94, 98, 99, 9A, 9B, 9C, A1, A3, A7, A8, A9, 5F。計算式が分かったものから順次数値表示に置き換える
- カテゴリ「診断・システム」を追加（PID 01, 1E, 4F, 50, 5F, 65, 90, 91, A9）
| グループ | 主な項目（PID） |
|---|---|
| 走行 | 車速 0D、回転数 0C、スロットル 11 / 45 / 47 / 48 / 8D / 4C、アクセルペダル 49 / 4A / 4B / 5A |
| エンジン | 負荷 04 / 43、点火時期 0E、要求・実・基準・フリクショントルク 61 / 62 / 63 / 8E、噴射時期 5D、シリンダー燃料量 A2 |
| バッテリー・電気 | バッテリー電圧（`ATRV`、全車）、ECU 電圧 42、ハイブリッドバッテリー残量 5B、12V 充電量（推定）、充電状態（判定） |
| 温度 | 冷却水 05 / 67、オイル 5C、吸気 0F / 68、外気 46、触媒 3C〜3F、排気 78 / 79、DPF 7C |
| 吸気・過給 | MAF 10 / 66、MAP 0B、大気圧 33、ブースト圧（計算）、ターボ回転数 74、排気圧 73、EGR 2C / 2D |
| 燃料 | 残量 2F、消費量 5E、燃料補正 06〜09 / 55〜58、目標 λ 44、燃料圧力 0A / 22 / 23 / 59、エタノール 52、エバポ 2E / 32 / 53 / 54 |
| 排ガス・O2 | O2 センサー電圧 14〜1B、空燃比センサー λ 24〜2B、DPF 差圧 7A |
| 距離・時間 | オドメーター A6、稼働時間 1F、DTC 消去後の距離・暖機回数・時間 31 / 30 / 4E、MIL 点灯中の距離・時間 21 / 4D |
| 車両情報 | 燃料の種類 51、OBD 規格 1C（文字で表示） |

- VIN は Mode 09 PID 02 で取得（ホーム画面）
- 車ごとの対応項目は `0100` / `0120` / … / `01C0` で確認する
- 表示しない PID：状態ビットの集合など 1 つの値で表せないもの（01、03、12、13、1D、1E、4F、50、64、65、69〜72、75〜77、7B、7D〜 など）。必要になったら個別に対応する

**バッテリー項目の考え方**
- `ATRV`（アダプターが OBD ポートで測る電圧）は PID 非対応の車でも取れるため、常に表示する
- 12V 充電量（推定）：エンジン停止中（回転数 0 または取得不可）の電圧から 11.8 V＝0%〜12.7 V＝100% で線形推定。作動中は「--」
- 充電状態：作動中の電圧で判定（13.2〜15.0 V 充電中 ／ 13.2 V 未満 充電不足 ／ 15.0 V 超 過充電の疑い）。停止中は「停止中」
- 劣化具合（SOH）・始動能力（CCA）は負荷試験が必要なため OBD では測れない
- PHEV の駆動用バッテリー（例：ボルボ T8）の詳細はメーカー独自の Mode 22 が必要（9.4 参照）

### 9.2 故障コード（DTC）※診断情報画面
- 読み取り：Mode 03 ／ 消去：Mode 04 ／ MIL と件数：Mode 01 PID `01`
- 形式は共通（P / C / B / U ＋ 4 桁）
- 共通コード（P0xxx、P2xxx、P34xx〜、C0/B0/U0 など）：説明文つき（`js/config/dtc-codes.js`）
- メーカー独自コード（P1xxx、P30xx〜P33xx など）：コードのみ表示
- 汎用 OBD で読めるのは主にエンジン系（排ガス関連）

### 9.3 車両情報
- VIN の先頭 3 文字（WMI）からメーカーを推定（`js/config/wmi.js`）、10 文字目から年式を推定（30 年周期のため現在年 +1 以下の最新年を採用）
- 車種名は VIN だけではオフラインで判定できないため、利用者の操作で NHTSA vPIC API に問い合わせる。北米向け以外の車は返らないことがある
- 国内専用車など、OBD で 17 桁の VIN を返さない車では「取得できませんでした」と表示

### 9.4 メーカー独自データ
- ボルボ独自の値（T8 のバッテリー残量、タイヤ空気圧など）は Mode 22 が必要で、公開情報が少ない → 「取れたらおまけ」扱い

### 9.5 PID の定義はデータとして持つ
- 各項目（PID、名前、単位、計算式、表示範囲、説明文）は `js/config/pids.js` にまとめる
- 将来のカスタム画面機能でも同じ定義を使う

## 11. Web Bluetooth の制約（設計の前提）
- 一覧はユーザー操作（ボタン）からしか開けない
- 一覧の見た目は変えられない（変えられるのは絞り込み条件だけ）
- **使うサービスの UUID は、一覧を開く時点で宣言が必要**（宣言していないと SecurityError）
- 基本的に、ページを開くたびに機器を選び直す（自動再接続は実験段階）
- バックグラウンドでは動かない → Wake Lock API で画面を点けたままにする
- ELM327 系の更新速度は 1 秒あたり数〜十数項目が目安

- 故障コードの消去など、書き込み系の操作は確認ダイアログを挟む
- 名前に「Volvo」「ELM327」は使わない（商標）。説明文で「ELM327 互換」と書くのは可

## B. GitHub Pages への公開
GitHub Actions（`.github/workflows/deploy.yml`）でデプロイする。`main` への push で自動デプロイ、Actions タブからの手動実行（workflow_dispatch）にも対応。公式アクション `actions/configure-pages` / `actions/upload-pages-artifact` / `actions/deploy-pages` を使用。

**初回の設定手順**
1. ファイル一式をリポジトリのルートにアップロードする
   - `.github` フォルダは名前が「.」で始まるため、macOS の Finder では表示されないことがある（`Command + Shift + .` で表示）。アップロード漏れに注意
2. リポジトリの **Settings → Pages** を開く
3. **Source** を「**GitHub Actions**」にする
4. **Actions** タブでワークフローが成功したことを確認する
5. <https://s1v.github.io/Stethos/> を開く

## C. 更新時の注意
- `sw.js` の `APP_VERSION` と `index.html` フッターのバージョン表記を更新してから push する（キャッシュ名が変わり、利用者の画面に「更新があります」が表示される）
- Service Worker はキャッシュ優先で配信するため、**バージョン（または `BUILD`）を変えないと利用者に変更が届かない**
- ファイルを追加したら `sw.js` の `ASSETS` にも追加する

## D. 既知の UUID を追加する
`js/config/known-uuids.js` に 1 行追加する。キャラクタリスティックは自動判別するため、サービス UUID だけでよい。

## E. 表示項目を追加する
`js/config/pids.js` の `PIDS` に定義（pid / key / name / unit / calc / min / max / decimals / group / desc）を追加する。ステータス画面とホームの「対応表示項目数」に自動で反映される。PID 以外の値（`ATRV` など）は `pid` の代わりに `cmd` を指定し、`obd.js` の `readPid` に取得処理を追加する。

## F. デバッグモード（後に削除）
- 起動：トップ画面の「デバッグモードで起動」、または URL に `?debug=1`（`&scenario=…` で状況指定）
- 状況：`normal`（DTC あり）/ `nodtc` / `unknown`（UUID 入力画面。疑似 UUID は `ABCD`）/ `connect-error` / `no-elm` / `disconnect`（20 秒後に切断）
- 疑似アダプターは ELM327 のように応答する（初期化、変化する車両データ、VIN `YV1DEBUG0K1234567`、DTC 4 件（共通・メーカー独自）、DTC 消去）
- **`pids.js` の全項目に対応している車として振る舞う**（項目を追加すると自動で疑似値も返す。値は計算式から逆算して表示範囲内で変化させる）
- 60 秒周期で「エンジン停止 15 秒 → 作動 45 秒」を繰り返し、バッテリー項目（充電量の推定・充電状態）の表示も確認できる
- Web Bluetooth 非対応ブラウザでも使える。デバッグ中はヘッダーに「DEBUG」バッジを表示

**削除手順**
1. `js/debug/` フォルダを削除
2. `index.html` の `<!-- DEBUG-START -->` 〜 `<!-- DEBUG-END -->` を削除
3. `js/app.js` 末尾の `// DEBUG-START` 〜 `// DEBUG-END` を削除
4. `sw.js` の `ASSETS` から `./js/debug/mock-adapter.js` を削除し、`VERSION` を更新

## G. Issue テンプレートと既知 UUID の自動登録
**テンプレート**（`.github/ISSUE_TEMPLATE/`）
- `adapter-report.yml`：アダプターの動作報告（製品名・サービス UUID・機器名・動作結果・端末・車種）。ラベル `adapter-report` が付く
- `bug-report.yml`：不具合の報告（ラベル `bug`）
- `feature-request.yml`：要望（ラベル `enhancement`）
- `config.yml`：空の Issue を無効化

**自動登録の流れ**
1. 利用者が「アダプターの動作報告」で Issue を作成
2. 管理者が内容を確認し、Issue に **`accepted` ラベル**を付ける
3. ワークフロー `adapter-report.yml` が動き、`add-known-uuid.mjs` が本文から UUID・製品名を取り出して
   - 形式チェック（不正・重複なら Issue にその旨をコメントして終了）
   - `known-uuids.js` の `// @auto-insert` の上に 1 行追加
   - `sw.js` の `BUILD` を +1（利用者のキャッシュを更新するため）
4. ブランチ `adapter/issue-番号` にコミットし、プルリクエストを作成。Issue に PR の URL をコメント
5. 管理者が PR をマージ → `main` への push でデプロイされ、Issue は自動でクローズ

- ラベルを付けられるのは書き込み権限のある人だけなので、第三者が勝手に登録することはできない。最終的にマージするかどうかも管理者が判断する
- 製品名はコードに埋め込むため、記号（`' " \` $ < > { } \`）を除去して 60 文字までに制限する

**初回だけ必要な設定**
1. **Settings → Actions → General → Workflow permissions** で「Read and write permissions」を選び、「Allow GitHub Actions to create and approve pull requests」にチェックを入れる
2. **Issues → Labels** でラベル `adapter-report` と `accepted` を作成する（`bug` `enhancement` は標準で存在する）
