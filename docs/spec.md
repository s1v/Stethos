# Stethos 仕様書

> No install needed. Read live vehicle data from BLE OBD2 adapters right in your browser via Web Bluetooth.

## 1. 概要
| 項目 | 内容 |
|---|---|
| アプリ名 | **Stethos**（聴診器 / Stethoscope に由来。「車の聴診器」） |
| 形態 | GitHub Pages で公開する静的 Web アプリ（HTML / CSS / JS、SPA） |
| PWA | **必須**（ホーム画面への追加、全画面表示、オフラインでの起動） |
| 配信 | ストア配信なし（URL を開くだけで使える） |
| 対象車両 | 車種を限定しない（OBD-II 対応車） |
| 開発に使う車 | ボルボ V90 Cross Country |
| GitHub Topics 案 | `obd2` `elm327` `web-bluetooth` `ble` `car` `vehicle-diagnostics` `pwa` `github-pages` |

## 2. 動作環境
| 環境 | 対応 | 備考 |
|---|---|---|
| Android + Chrome | ◯ | URL を開くだけで使える |
| Android + Edge / Samsung Internet | ◯ | おおむね対応 |
| iPhone + Safari / Chrome | ✕ | WebKit が Web Bluetooth 非対応 |
| iPhone + **Bluefy** | ◯ | 無料の Web Bluetooth 対応ブラウザ |
| PC + Chrome / Edge | ◯ | 開発・デバッグ用 |

- 非対応ブラウザで開いた場合は、対応ブラウザを案内する（デバッグモードは非対応ブラウザでも使える）。
- GitHub Pages は HTTPS なので、Web Bluetooth と Service Worker の HTTPS 必須という条件を満たしている。

## 3. 対応アダプター
- **ELM327 互換の BLE 版のみ**
  - Bluetooth Classic（SPP）版：✕（Web Bluetooth は BLE 専用）
  - Wi-Fi 版：✕（ブラウザは生の TCP 通信ができない。HTTPS から暗号化なしのローカル通信もブロックされる）
- 開発用の実機：**JFIND JF327**（BLE、Bluetooth 5.1、PIC18F25K80、V1.5）
  - UUID は実機を nRF Connect で確認予定

## 4. 画面構成（SPA）
ページを移動すると BLE の接続が切れるため、**1 ページ内で表示を切り替える**。

### 4.1 画面一覧
| 画面 | 役割 | 表示タイミング |
|---|---|---|
| トップ | 接続ボタン、接続前の案内、詳細設定（UUID 指定・任意）、UUID 管理画面への導線、デバッグモードの入口 | 起動時・切断後 |
| UUID 入力 | 未登録アダプター用の UUID 入力 | 既知の UUID が見つからなかったとき |
| UUID 管理 | 保存した UUID の一覧・削除 | トップから移動 |
| ホーム | **サマリー情報のみ**を表示 | 接続完了後 |
| ステータス | リアルタイムの車両データ | メニューから移動 |
| 診断情報 | 故障コード（DTC）の一覧・消去 | メニューから移動 |

### 4.2 画面の遷移
```
[トップ] ──→ [UUID 管理] ──→ [トップ]
   │
   │ 接続
   ├──（未登録）→ [UUID 入力] → 再選択 ─┐
   ▼                                  │
[ホーム] ←────────────────────────────┘
   │
   │ 右上のメニュー
   ├ ホーム
   ├ ステータス
   ├ 診断情報
   └ 切断 → 確認 → [トップ]
```

### 4.3 共通ヘッダー（接続後の画面）
- 対象：ホーム / ステータス / 診断情報
- 左：画面名、接続状態（接続中 / 切断）、デバッグモード中は「DEBUG」バッジ
- **右上：メニューボタン**（ハンバーガーアイコン）
- メニュー：ホーム / ステータス / 診断情報 / 切断（確認ダイアログ → 切断 → トップ画面へ）
- 予期せず接続が切れた場合も、通知を表示してトップ画面へ戻る。

### 4.4 トップ画面
- 接続ボタン
- 接続前の案内（ドングルを車に挿している／イグニッション ON／他の OBD アプリは閉じている／次の画面で「OBDII」などの名前の機器を選ぶ）
- 詳細設定（折りたたみ・任意）：今回の接続で使うサービス UUID を入力
- **UUID 管理画面へのリンク**
- デバッグモードで起動するボタン（「13. デバッグモード」参照）

### 4.5 ホーム画面（サマリーのみ）
| 項目 | 内容 |
|---|---|
| 接続中のアダプター | 機器名 |
| 車両 | VIN（取得できた場合） |
| **DTC 数** | 故障コードの件数（0 件なら「異常なし」）。タップで診断情報画面へ |
| MIL（チェックランプ） | 点灯 / 消灯 |
| ECU 電圧 | 現在の値 |
| 対応 PID 数 | 車が対応している項目の数 |

### 4.6 ステータス画面
- 標準の OBD-II 項目をリアルタイムで表示（「9. 表示するデータ」参照）
- 車が対応していない項目は表示しない、またはグレーアウトする
- 表示中は Wake Lock で画面を点けたままにする

### 4.7 診断情報画面
- DTC の一覧（コード、共通 / メーカー独自の区別、共通コードは説明文）
- 再読み込みボタン
- DTC 消去ボタン（確認ダイアログを必ず挟む）

## 5. 接続の流れ
### 5.1 一覧の表示と UUID の宣言
| 設定 | 役割 | 本アプリの仕様 |
|---|---|---|
| 一覧に何を表示するか | どの機器を一覧に並べるか | **全ての BLE 機器を表示**（名前などで絞り込まない） |
| どのサービスを使うか（宣言） | 接続後にアクセスできるサービス | 下記 3 種類の UUID をまとめて宣言 |

- 宣言は一覧の表示には影響しない。宣言にない機器も一覧に出て、接続もできる。
- ただし、接続後に使えるサービスは宣言した UUID だけ（宣言していないと SecurityError）。

宣言する UUID：① 既知の UUID リスト ／ ② 保存済みの UUID ／ ③ 詳細設定で入力した UUID

### 5.2 手順
1. 接続ボタンを押す
2. Web Bluetooth の一覧を開く（全機器を表示、①〜③を宣言）
3. 利用者がアダプターを選ぶ
4. 宣言したサービスがあるか確認する

**A. 既知の UUID が見つかった場合**：write / notify のキャラクタリスティックを性質から自動判別 → `ATZ` などで ELM327 の応答を確認・初期化 → ホーム画面へ

**B. 既知の UUID が見つからなかった場合**：UUID 入力画面（選んだ機器名、nRF Connect での調べ方を案内）→ UUID を入力して「接続」→ 一覧がもう一度開く → 同じアダプターを選び直す → 入力した UUID で確認し、OK なら localStorage に保存 → ホーム画面へ

→ 2 回目以降は保存した UUID も宣言に含まれるので、A の流れになる。

### 5.3 選ぶ回数
| 利用者 | 流れ | 選ぶ回数 |
|---|---|---|
| 既知のアダプター（大多数） | 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知っている | 詳細設定で入力 → 接続 → 選ぶ | 1 回 |
| 未知のアダプター・UUID を知らない | 接続 → 選ぶ → 入力 → もう一度選ぶ | 2 回（初回のみ） |

## 6. 既知の UUID
| サービス UUID | 主な製品 | 確認状況 |
|---|---|---|
| `FFF0` | 安価な ELM327 BLE 系 | 公開情報ベース |
| `FFE0` | HM-10 系モジュール | 公開情報ベース |
| `e7810a71-73ae-499d-8c15-faa9aef0c3f2` | Vgate iCar Pro BLE、OBDLink CX など | 公開情報ベース |
| Nordic UART Service など | BLE でシリアル通信をする部品で一般的 | 公開情報ベース |
| （JF327 の UUID） | JFIND JF327 | 実機確認済み（nRF Connect で確認後に記入） |

- キャラクタリスティックは性質（write / notify）から自動で判別するため、**サービス UUID のみ管理する**。
- 未確認の UUID を宣言しても害はないため、候補は多めに入れておく。
- 動作報告は GitHub の Issue で受け付け、確認状況を更新する。
- 既知の UUID は設定ファイル `js/config/known-uuids.js` にまとめる。

## 7. UUID 入力・管理の仕様
### 7.1 入力
- 入力するのは**サービスの UUID のみ**
- 短い形式（`FFF0`）と長い形式（128bit）の両方を受け付ける
- 大文字・小文字や `0x` の有無は自動で整える
- 形式が正しくなければボタンを無効にする
- 接続に成功した UUID だけを localStorage に保存する

### 7.2 管理
- トップ画面から移動する（未接続の状態で使う）
- 保存した UUID の一覧（UUID、接続した機器名、保存日時）
- 個別削除（確認ダイアログあり）
- 既知の UUID リストは参考として表示のみ（削除不可）

## 8. エラーの出し分け
| 原因 | 表示・動作 |
|---|---|
| Web Bluetooth 非対応 | 対応ブラウザ（Android：Chrome、iPhone：Bluefy）を案内 |
| Bluetooth がオフ | オンにするよう案内 |
| 一覧でキャンセル | トップ（または入力画面）に戻る |
| 機器が見つからない・つながらない | イグニッション ON、他の OBD アプリを閉じたかを確認するよう案内 |
| 既知の UUID がない | UUID 入力画面へ |
| 入力した UUID のサービスがない | 入力内容を残して入力画面に戻る |
| 送信用・受信用の入口がない | 別の UUID を試すよう案内 |
| ELM327 の応答がない | ELM327 互換ではない可能性を案内 |
| 接続中に切断された | 通知を表示してトップ画面へ |

## 9. 表示するデータ
### 9.1 標準の OBD-II 項目（Mode 01）※ステータス画面
- 走行：車速、エンジン回転数、エンジン負荷、スロットル開度
- 温度：冷却水温、吸気温、外気温、触媒温度
- 吸気・過給：吸入空気量（MAF）、吸気圧（MAP）→ ブースト圧を計算
- 燃料：燃料補正値、O2 センサー、燃料残量（対応している車のみ）
- 電気：ECU 電圧
- その他：エンジン稼働時間、VIN（Mode 09）
- 車ごとの対応項目は `0100` などで確認する

### 9.2 故障コード（DTC）※診断情報画面
- 読み取り：Mode 03 ／ 消去：Mode 04
- MIL の状態と件数：Mode 01 PID `01`
- 形式は共通（P / C / B / U ＋ 4 桁）
- 共通コード（P0xxx など）：説明文つきで表示
- メーカー独自コード（P1xxx など）：コードのみ表示
- 汎用 OBD で読めるのは主にエンジン系（排ガス関連）

### 9.3 メーカー独自データ
- ボルボ独自の値（T8 のバッテリー残量、タイヤ空気圧など）は Mode 22 が必要で、公開情報が少ない → 「取れたらおまけ」扱い

### 9.4 PID の定義はデータとして持つ
- 各項目（PID、名前、単位、計算式、表示範囲）は定義ファイル `js/config/pids.js` にまとめる。
- 将来のカスタム画面機能でも同じ定義を使う。

## 10. PWA
| 項目 | 内容 |
|---|---|
| マニフェスト | `manifest.webmanifest`（名前、アイコン、テーマカラー、`display: standalone`） |
| アイコン | 192px / 512px、maskable 対応 |
| Service Worker | `sw.js`。アプリ本体のファイルをキャッシュし、オフラインでも起動できるようにする |
| 更新 | 新しいバージョンがあれば「更新があります」と表示し、再読み込みで反映する |
| パス | GitHub Pages はサブパスで公開されるため、**全て相対パス**で記述する |

- iPhone の Bluefy でも動くよう、PWA 非対応の環境でも通常の Web ページとして問題なく使えるようにする。
- オフラインで起動はできるが、車との通信は BLE なのでネット接続は不要。

## 11. 成果物とリポジトリ構成
- **zip ファイルで提出**する。展開したファイル群を、そのまま GitHub リポジトリのルートにアップロードすれば動く構成にする。ビルド作業は不要。
- `.github` フォルダは macOS の Finder などでは表示されないことがある（`Command + Shift + .` で表示）。

## 12. GitHub Pages のデプロイ
- GitHub Actions（`.github/workflows/deploy.yml`）。`main` への push で自動デプロイ、workflow_dispatch にも対応。
- 公式アクション（`actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`）を使う。
- 初回の設定手順は README を参照。

## 13. デバッグモード（後に削除）
- 起動：トップ画面の「デバッグモードで起動」ボタン、または URL に `?debug=1`。Web Bluetooth 非対応ブラウザでも使える。
- 疑似アダプター（`js/debug/mock-adapter.js`）が ELM327 のように応答する（初期化コマンド、変化する車両データ、DTC 数件（共通・メーカー独自）、DTC 消去）。
- 再現できる状況：未登録アダプター、接続エラー・切断、DTC 0 件。
- デバッグモード中は、ヘッダーに「DEBUG」バッジを常に表示する。
- デバッグ用コードは `js/debug/` にまとめ、本体との接点は最小限にする。削除手順は README に記載。

## 14. Web Bluetooth の制約（設計の前提）
- 一覧はユーザー操作（ボタン）からしか開けない
- 一覧の見た目は変えられない（変えられるのは絞り込み条件だけ）
- **使うサービスの UUID は、一覧を開く時点で宣言が必要**（宣言していないと SecurityError）
- 基本的に、ページを開くたびに機器を選び直す（自動再接続は実験段階）
- バックグラウンドでは動かない → Wake Lock API で画面を点けたままにする
- ELM327 系の更新速度は 1 秒あたり数〜十数項目が目安

## 15. 将来の拡張
### 15.1 カスタム画面（搭載予定）
- 利用者が表示する項目やレイアウトを自由に組み合わせた画面を作れる機能。メニューにカスタム画面を追加できるようにする想定。
- 今回の実装で配慮すること：データ取得（`obd.js`）と表示（`screens/`）の分離、PID 定義のデータ化（`js/config/pids.js`）、メニュー項目のデータ化（`js/config/menu.js`）。

### 15.2 その他
- アダプター情報を Issue で報告してもらい、既知の UUID を増やす
- 走行ログ（IndexedDB に保存、CSV で書き出し）
- グラフ表示
- GPS との連携
- 0-100km/h 加速タイム計測

## 16. 運用上の注意
- 走行中の画面操作は避け、表示専用の設計にする
- 故障コードの消去など、書き込み系の操作は確認ダイアログを挟む
- 名前に「Volvo」「ELM327」は使わない（商標）。説明文で「ELM327 互換」と書くのは可
